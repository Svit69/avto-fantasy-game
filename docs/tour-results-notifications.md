# Рассылка итогов тура

## Когда отправляется

- Планировщик работает внутри HTTP-сервера, проверка раз в минуту; дополнительный cron не нужен.
- Существующий `npm run notify:draft` тоже поддерживает итоги. Общая блокировка исключает одновременную обработку с планировщиками кружков и итогов.
- Наступил `endsAt` тура; все неотменённые матчи его календаря завершены и имеют импортированные данные игроков.
- Очки рассчитаны теми же `MonthlyPlayerPointsCalculator` и `StandingsCalculator`, что и `/api/standings`: сумма средних ФО игроков состава, не сумма ФО матчей.
- Итоговая таблица должна оставаться стабильной 30 минут. Изменение очков или отсутствие финального протокола сбрасывает ожидание.
- Задержка настраивается `TOUR_RESULTS_SETTLE_MS` (по умолчанию 1800000); для тестов можно задать 0.
- При первом включении сохраняется время активации: уже закончившиеся туры не запускают старую массовую рассылку.
- После перезапуска незавершённые отправки догоняются; готовый снимок итогов остаётся тем же. Поздние ручные исправления не запускают новую рассылку автоматически.
- Если через шесть часов после конца тура не хватает финальных данных, админы получают одно отдельное предупреждение. Победитель до проверки не поздравляется.

## Получатели

- Пользователь с `place: 1` получает поздравление с названием тура, результатом состава и кнопкой приложения.
- Ничьи соответствуют таблице: поздравляются все разделившие первое место, без выбора по алфавиту.
- `TELEGRAM_ADMIN_IDS` получают ТОП-3 места и контакты: имя, ФО, Telegram username при наличии, ссылка на профиль по ID, телефон и email из базы.
- При равенстве мест в ТОП-3 может быть больше трёх участников. Большой отчёт разбивается на отдельные сообщения.
- Отсутствующие контакты отмечаются явно. Username сохраняется при последующем входе через Telegram; для старых пользователей остаются ID и ранее сохранённые контакты.
- Контакты доступны только в админском сообщении, не добавляются в поздравление или публичную таблицу.
- Если участников нет, поздравления нет; админ получает сообщение о пустой таблице.
- Призы и сроки связи в поздравлении не обещаются: условия награждения в системе не заданы.

## Надёжность

- Ключи отправок уникальны для тура, получателя и типа сообщения; обычный повторный запуск или перезапуск не дублирует успешные отправки.
- Успех проверяется по HTTP и JSON `ok` Telegram. Отказ не отмечается как доставленный.
- Сетевой обрыв после принятия сообщения Telegram оставляет неоднозначность: существующий текстовый worker может повторить отправку. Гарантии exactly-once для Telegram нет.
- `tour-results-activation.json` и `tour-result-*.json` находятся в общей `RUNTIME_STATE_DIRECTORY` (по умолчанию `storage/runtime`). Снимки содержат контакты лидеров; не публикуйте директорию и включите её в защищённые резервные копии.
- `TOUR_RESULTS_NOTIFICATIONS_ENABLED=false` отключает итоги в планировщике и worker, независимо от кружков.
- Данные пользователей сохраняются в существующем JSON payload; миграция PostgreSQL не требуется.

## Развёртывание

```bash
git pull && npm ci && npm run check && pm2 restart avto-fantasy --update-env
```

В логах появится `tour_results_scheduler_started`. Проверки: `npm run test:results`, `npm run check`.
Автотесты используют подставной Telegram-клиент и временное хранилище; реальные сообщения пользователям не отправляются.
