# Помощник стоимости игроков

В админ-боте: `/admin` → «Помощник стоимости»; «Статистика всех игроков» показывает причины решений.
Расчёт ничего не записывает в цены и не меняет составы пользователей.
Кнопки «Изменить цену» открывают существующий ручной ввод стоимости.

## Данные

- Весь регулярный сезон (июль–июнь), без предсезонки и предыдущего сезона; ограничения тремя турами нет.
- Только завершённые импортированные матчи из календаря, без будущих матчей.
- Последний импорт каждого матча; старые строки игроков не восстанавливаются.
- Все фактически сыгранные матчи игрока, включая переходы между лигами.
- ФО уже содержат коэффициент лиги. Повторного умножения нет.
- Отсутствие строки игрока не равно нулю; настоящий ноль учитывается.
- Игроки, покинувшие игру, исключены.

## Форма и последние игры

1. Матчи игрока сортируются по дате; считаются среднее, медиана и количество последних 5, 10 и всех игр сезона.
2. Веса окон: 0,5 / 0,3 / 0,2. Окна пересекаются: недавняя форма намеренно весит больше.
3. Вес окна умножается на `min(матчи / размер, 1)`; для сезонного веса размер уверенности = 10. Веса нормализуются.
4. Для оценки формы результаты каждого окна ограничиваются его медианой ± `max(15, abs(медиана))`.
5. База формы: взвешенные `0,7 × ограниченное среднее + 0,3 × ограниченная медиана`. Реальные ФО в отчёте не меняются.
6. Последние 1–2 игры сравниваются с медианой до 10 матчей перед ними, без привязки к туру.
7. Сильная игра: ФО выше этой медианы минимум на `max(10, abs(медиана) × 0,5)`.
8. Поправка: превышение среднего последних игр над базой, максимум `max(15, abs(база) × 0,75)`, с весом 15% для одного всплеска и 50% для двух.
9. Разброс последних 10: стандартное отклонение / `max(abs(среднее), 10)` по реальным ФО; стабильность: `1 / (1 + разброс)`.
10. Стабильная форма последних 5: минимум 3 игры, не менее 80% положительных матчей, разброс не выше 0,35.

Для цены нужны 3 матча сезона; полевым также 3 подходящих игрока, вратарям — 1. Матч в текущем туре не требуется.
При 1–2 играх статистика предварительная, но видна в списке всех игроков; нулевая история показывается отдельно.
Если загружено менее 80% последних 10 матчей команды, начавшихся более 4 часов назад,
её рекомендации блокируются. Пустой протокол без ФО не считается загруженным.

## Бюджет и рекомендации

Бюджет и лимит клуба берутся из `FantasyRosterRules`: сейчас 90к и 4 игрока. Состав: 3 НАП + 2 ЗАЩ + 1 ВРТ.
Цена по группе = форма / взвешенная медиана отдачи ФО на 1к других игроков текущей команды и позиции. Вес = надёжность истории сопоставимого игрока.
Бюджетный ориентир = бюджет × форма игрока / суммарная форма сильнейшего допустимого состава среди игроков с достаточными данными и допустимой полнотой протоколов команды.
Расчётная цена = `max(1, 60% цены по группе + 40% бюджетного ориентира)`; если полный опорный состав не собрать, используется только цена по группе.
Число матчей для надёжности ограничено 10. База: `n / (n + 5) × (0,5 + 0,5 × стабильность)`; для вратаря знаменатель `n + 8`.
После 21 дня без матчей применяется множитель `max(0,5, 1 − (дни − 21) / 120)`. Разброс между игроками группы также снижает надёжность. Это эвристический коэффициент осторожности, не вероятность.
Осторожный ориентир = текущая цена + `(расчётная цена − текущая цена) × надёжность`. Порог отклонения: одновременно 0,75к и 12% цены; шаг ±1к, минимум 1к.
Рост подтверждается медианой последних 5 минимум на 10% выше группы либо двумя сильными играми; снижение — медианой на 10% ниже либо расчётной ценой ниже 75% текущей.
Сначала учитываются снижения, затем повышения по убыванию сглаженного отклонения. Каждый шаг сохраняет доступный состав с каждым одобренным игроком; иначе отклоняется только этот шаг. Алгоритм приоритетный, не глобальный оптимум набора изменений.
Точный подбор учитывает позиции, уникальность игроков и лимит клуба; в отчёте показываются минимальные стоимости до и после.
Это подсказка: травмы, роль, корректность протоколов проверяет админ. Повторный расчёт может предложить ещё один шаг; лимита изменений за тур нет.
Проверка: `npm run test:prices` (входит в `npm run check`). Новых зависимостей и миграций нет.
